# Audit Remediation Assumptions & Conservative Decisions

This document records all autonomous engineering decisions made under the conservative default rule across Tickets T1 through T7.

| Decision ID  |        Ticket / Scope        | Context & Options                                                          | Chosen Decision (Most Conservative)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Rationale / ADR Reference                                                                                                               |
| :----------- | :--------------------------: | :------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------------------------------------------------------------------------------- |
| **A-S1**     |      **T1** (Security)       | Master key validation: What if `KEEL_MASTER_KEY` is invalid at startup?    | When `KEEL_MASTER_KEY` is unset, < 32 chars, < 12 distinct chars, contains placeholder values ('your-random', 'change-me'), or equals default string: log loud startup error, disable vault functionality, but allow server to start so non-vault endpoints remain operational. Vault-dependent routes return 503 Service Unavailable.                                                                                                                                                                                                                                                                        | **ADR-0013**: S1 pre-made decision; prevents unencrypted/insecure vault state while preserving server observability.                    |
| **A-S2**     |      **T1** (Security)       | Throttling storage & scope: Persist failed login attempts in SQLite.       | Table `auth_rate_limits (key TEXT PRIMARY KEY, attempts INTEGER, first_attempt_ms INTEGER, locked_until_ms INTEGER)`. Exponential backoff starts after 5 failed attempts within 15m. Applied to `/login`, `/step-up`, `/bootstrap`.                                                                                                                                                                                                                                                                                                                                                                           | **ADR-0013**: S2 pre-made decision; survives server restarts and node cluster reboots.                                                  |
| **A-FMT**    |      **T1** (Security)       | Versioned format migration: Support legacy hashes and ciphertexts.         | Hashes prefixed with version string `argon2id$v=1$...`. Legacy unversioned hashes re-hashed on valid login. Vault ciphertexts versioned `v1:...`. Legacy ciphertexts decrypted and re-encrypted on write.                                                                                                                                                                                                                                                                                                                                                                                                     | **ADR-0013**: Eliminates silent breaking changes while transparently migrating storage.                                                 |
| **A-R1**     |   **T2** (Replay Realism)    | Exit adverse slippage & stress multiplier.                                 | Slippage penalty applied to stop market exits and liquidation market exits, but NOT to limit take-profit fills. Cost stress multiplier scales both fees AND slippage. Shared in `@keel/core/execution.ts`.                                                                                                                                                                                                                                                                                                                                                                                                    | **ADR-0014**: R1 pre-made decision; prevents optimistic fill assumptions and establishes bit-for-bit parity.                            |
| **A-R2**     |  **T3** (Trial Accounting)   | Trial counter definition & sequence.                                       | New table `research_trials (strategy_id TEXT, parameter_hash TEXT, instrument_id TEXT, timeframe TEXT, first_recorded_at_ms INTEGER PRIMARY KEY)`. Counter strictly non-decreasing based on distinct trials. Replaced `INSERT OR REPLACE` with plain `INSERT` in `experiments` with auto-incrementing `sequence`.                                                                                                                                                                                                                                                                                             | **ADR-0015**: R2 pre-made decision; immutable audit trail of all research trials.                                                       |
| **A-R4**     | **T3** (Holdout Quarantine)  | 2026 Holdout quarantine enforcement.                                       | Reject any request accessing data >= `SEALED_2026_HOLDOUT_START_TS` unless `allowHoldoutAccess === true` AND a single-use token row exists in `holdout_tokens` table. Single-use token is consumed upon access. Walk-forward folds reject confirmed bars in holdout.                                                                                                                                                                                                                                                                                                                                          | **ADR-0015** / **ADR-0011**: R4 pre-made decision; unspent holdout partition quarantine.                                                |
| **A-R3**     |  **T4** (Report Integrity)   | Benchmark gates & multi-path random entry distribution.                    | Evaluate $\ge 200$ Monte Carlo paths for random entry baseline. Hardened `replayGatePassed` to require beating Buy & Hold Sharpe and beating the 75th percentile of the random entry distribution. Enforces isolated single-strategy walk-forward evaluation.                                                                                                                                                                                                                                                                                                                                                 | **ADR-0016**: R3 pre-made decision; prevents luck, selection bias, and candidate cross-contamination.                                   |
| **A-R6**     | **T5** (Scheduler Catch-up)  | Confirmed bar processing backlog.                                          | Process all unprocessed bars in chronological order, capped at 500 bars per step. Enforce bar idempotency per `(instrument, strategy)`. Default `schedulerStrategies` configuration is empty (`[]`).                                                                                                                                                                                                                                                                                                                                                                                                          | **ADR-0017**: R6 pre-made decision; prevents missed fills/funding while bounding memory/runtime and preventing default execution.       |
| **A-BRK**    | **T6** (Broker Truthfulness) | Exchange fill polling, algo order cancellation, & DMS honesty.             | Poll real fill price and fees from OKX; record `SUBMITTED` when unconfirmed. On emergency flatten, explicitly cancel resting conditional and OCO algo orders via `cancel-algo-orders` rather than relying on `cancel-all-after` with `timeOut: "0"`. Clean `attachAlgoOrds` to confirmed OKX V5 REST parameters. Return `healthy: false` when credentials absent.                                                                                                                                                                                                                                             | **ADR-0018**: Eliminates fabricated fill prices, resting order abandonment, and unverified schema rejections.                           |
| **A-SHADOW** |     **T7** (Shadow Gate)     | Shadow pick lifecycle & resolution.                                        | Record shadow pick with signal bar timestamp; dedupe per `(strategy, instrument, bar)`. Resolve later against subsequent bars into hypothetical $R$ using next-bar open entry and gap-aware intrabar exits. Require non-negative resolved expectancy ($R \ge 0$) and at least `shadowMinTrades`.                                                                                                                                                                                                                                                                                                              | **ADR-0019**: Prevents unconfirmed shadow trades from counting toward promotion.                                                        |
| **A-PROM**   | **T7** (Promotion Re-Check)  | Live eligibility validation at promote time.                               | `POST /api/v1/promotion/promote` re-evaluates all gate criteria at runtime against live database state. Strictly rejects promotion if live evaluation fails, completely eliminating trust in pre-stored `eligibleNextStage`.                                                                                                                                                                                                                                                                                                                                                                                  | **ADR-0019**: Guarantees that only strategies currently qualifying can be promoted.                                                     |
| **A-C2**     |       **T1 (Round 3)**       | Scheduler historical bar replay & 2026 quarantine.                         | Newly enabled `(instrument, strategy)` anchors at latest confirmed bar in SQLite at enabling time. Bars $\le$ anchor are never evaluated. Historical bars with `openTs >= 1767225600000` excluded unless live present ($\|nowMs - closeTs\| \le 2h$). Zero ticks on 20,000 history bars.                                                                                                                                                                                                                                                                                                                      | C2 pre-made decision. Prevents historical bar replay, paper trade count inflation, and holdout contamination.                           |
| **A-C1**     |       **T2 (Round 3)**       | Replay 2026 seal wiring, effective range, & atomic token consumption.      | Replay seal check uses requested/effective range `[effectiveFromTs, effectiveToTs]` rather than stored coverage. Single-use holdout token is consumed ONLY inside `saveExperiment` in an atomic SQLite transaction upon successful run, never upfront before simulation or data lookup. Server route never self-grants `allowHoldoutAccess = true`.                                                                                                                                                                                                                                                           | C1 pre-made decision. Prevents holdout violation false-positives on in-sample replays and token consumption on failed runs.             |
| **A-C3**     |       **T3 (Round 3)**       | Broker truthfulness remainder (C3a-d): strict ID equality, fills, flatten. | Stop confirmation matches strictly by ID equality (`algoClOrdId`, `attachAlgoClOrdId`, `algoId`), removing single-pending shortcut. Unconfirmed fill on submit raises `CRITICAL` alert, emergency flattens, and throws. Reconcile polls `/trade/fills` before declaring missing positions as drift; matching exit fill records real PnL/fee locally. Flatten confirms close fills via `/trade/order` before posting PnL; unconfirmed close leaves position `OPEN` with zero fabricated PnL and emits `CRITICAL` alert. Orders pass `tdMode` (`isolated` default) and `posSide` (`long`/`short` when non-net). | C3a-d audit decisions. Prevents false stop matches, false-positive drift flattening, fabricated close PnL, and untracked fills.         |
| **A-T5**     |       **T5 (Round 3)**       | Strategy Spec V1 schema, canonical hash, and interpreter.                  | StrategySpecV1 uses Zod schema with bounded indicator whitelist and AST expressions. Parameter hash (`specHash`) is recursive sorted-key canonical JSON sha256. `SpecStrategy` executes purely causally against `FeatureSnapshot`. Built-in strategies (`donchian-trend-v1`, `vol-mean-reversion-v1`, `vol-momentum-v1`) have exact parity specs. `synthetic` flag strictly blocks promotion to Demo or Live.                                                                                                                                                                                                 | ADR-0020. Declarative strategy AST with zero arbitrary code execution, zero floats for accounting, and deterministic evaluation.        |
| **A-T6**     |       **T6 (Round 3)**       | Strategy Spec repository, API endpoints, trial coupling, and quarantine.   | `StrategySpecRepository` persists specs in `strategy_specs` and active names in `strategy_spec_names`. Inserting a new spec automatically increments monotonic `research_trials` counter. `POST /api/v1/specs` validates AST and registers spec; `GET /api/v1/specs/:hash` provides deterministic English AST description. `POST /api/v1/promotion/promote` rejects synthetic specs with 403 Forbidden. Web dashboard includes dedicated specs registry view with quarantine badges and AST inspector.                                                                                                        | ADR-0021. Research trial universe is strictly monotonically accounted. Synthetic strategies are permanently quarantined from execution. |
